# Team Rules

1. Read your TASKS/*.md file before starting work.

2. Work primarily inside your assigned module.
   - Purva: frontend/purva/
   - Janhavi: frontend/janhavi/
   - Tanmay: frontend/tanmay/
   - Amey: backend/amey/

3. Do not modify another member's owned module without coordination.

4. Do not casually modify shared/core files.
   Examples:
   - frontend entry point
   - router
   - global CSS
   - shared components
   - package files
   - environment/config files
   If such a change is necessary, communicate with the team first.

5. Never push directly to main.

6. Use feature branches.
   Suggested names:
   - feature/purva-dashboard
   - feature/janhavi-tasks
   - feature/tanmay-settings
   - feature/amey-backend

7. Pull/fetch latest changes before starting work.

8. Test before pushing.

9. Use Pull Requests for meaningful changes.

10. Do not merge untested code.

11. Do not overbuild.

12. MVP first.

13. If a feature becomes too expensive or risky for the remaining time, simplify it instead of rebuilding the entire project.

14. AI-generated code must be understood before being accepted.

15. AI must not modify unrelated areas.

16. Meaningful AI-driven technical decisions must be recorded in DECISIONS.md.

17. Major execution/data-flow changes should be reflected in FLOW.md.

18. Keep the codebase clean.

19. Do not create folders just because they are conventional. Create them when the project actually requires them.

20. Architecture must follow the problem and solution, not the other way around.
